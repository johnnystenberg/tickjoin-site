Integritet

Den här sidan beskriver vilka behörigheter Tickjoin begär i Microsoft 365 och Google, vad appen gör med kalenderdata och hur åtkomsten återkallas. Senast uppdaterad 23 oktober 2026.

Kort sagt

  • Kalenderdata lämnar aldrig telefonen. Appen anropar Microsoft Graph och Google Calendar API direkt från enheten. Ingen server hos oss tar emot tokens eller mötesinnehåll.
  • Bara läsbehörighet. Tickjoin skapar, ändrar eller svarar aldrig på möten och har ingen åtkomst till e-post eller filer.
  • Ingen analys eller spårning. Appen innehåller inga analys- eller reklam-SDK:er.

Behörigheter som begärs i Google

ScopeVarför

Användning av data från Google

Tickjoins användning och överföring av information som tas emot från Googles API:er följer Google API Services User Data Policy, inklusive kraven på begränsad användning (Limited Use). Det innebär att data från Google:

  • bara används för att visa användarens möten och påminna om dem i appen,
  • aldrig överförs till JMS Software & Consulting eller till tredje part,
  • aldrig används för reklam och aldrig säljs,
  • aldrig läses av människor,
  • aldrig används för att träna AI- eller maskininlärningsmodeller.

Vad som lagras och var

  • Möten för de kommande sju dagarna lagras i en lokal databas på telefonen, skyddad av iOS dataskydd.
  • Inloggningstokens hanteras av Microsofts inloggningsbibliotek (MSAL) och lagras i iOS nyckelring. För Google lagras en refresh-token i iOS nyckelring; åtkomsttoken finns bara i minnet.
  • Inget skickas till JMS Software & Consulting eller till tredje part.
  • När användaren loggar ut ur ett konto i appen raderas tokens, möten och schemalagda alarm för kontot från telefonen. För Google-konton återkallas dessutom behörigheten hos Google.

Privacy

This page describes the Microsoft 365 and Google permissions Tickjoin requests, what the app does with calendar data and how access is revoked. Last updated 23 October 2026.

In short

  • Calendar data never leaves the phone. The app calls Microsoft Graph and the Google Calendar API directly from the device. No server of ours receives tokens or meeting content.
  • Read-only. Tickjoin never creates, changes or responds to meetings and has no access to mail or files.
  • No analytics or tracking. The app contains no analytics or advertising SDKs.

Requested Microsoft 365 permissions

Permission (delegated)Why
Calendars.ReadRead the user's meetings for the next seven days: time, title, location, meeting link and response status. The meeting body is only read to find the meeting link; the text itself is not stored.
offline_accessKeep the calendar up to date without the user signing in again.
User.ReadShow which account is connected (name and email address).
Microsoft Mobile Application Management: DeviceManagementManagedApps.ReadWriteOnly used by the Intune App SDK when the organization requires app protection: register the app with Intune and fetch the organization's protection policy. See App protection with Intune.

The app requests no application permissions and no write permissions.

Requested Google permissions

ScopeWhy
https://www.googleapis.com/auth/calendar.readonlyRead the user's calendar list and their meetings for the next seven days: time, title, location, meeting link and response status. The event description is only read to find the meeting link; the text itself is not stored. The account's email address is taken from the primary calendar to show which account is connected.

No other Google permissions are requested. The app has no access to Gmail, Drive or contacts.

Use of Google user data

Tickjoin's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. Data from Google:

  • is only used to show the user's meetings and remind them about them in the app,
  • is never transferred to JMS Software & Consulting or to any third party,
  • is never used for advertising and never sold,
  • is never read by humans,
  • is never used to train AI or machine learning models.

What is stored and where

  • Meetings for the next seven days are stored in a local database on the phone, protected by iOS Data Protection.
  • Sign-in tokens are handled by Microsoft's authentication library (MSAL) and stored in the iOS keychain. For Google, a refresh token is stored in the iOS keychain; the access token is only kept in memory.
  • Nothing is sent to JMS Software & Consulting or to any third party.
  • Signing out of an account in the app deletes its tokens, meetings and scheduled alarms from the phone. For Google accounts, access is also revoked at Google.

Information for IT administrators

How to approve Tickjoin for your organization, the app's registration in Microsoft Entra and app protection with Intune are described at tickjoin.com/it.

Revoking access

  • Users: sign the account out in Tickjoin under Settings, or remove the app at myapps.microsoft.com (work accounts) or account.live.com/consent/Manage (personal accounts). Google accounts are removed at myaccount.google.com/connections.
  • Administrators: in the Microsoft Entra admin center under Enterprise applications → Tickjoin → Permissions you can revoke consent or delete the app.
